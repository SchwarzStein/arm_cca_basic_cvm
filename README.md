# ARM CCA basic CVM

A small experimental AArch64 virtual machine monitor demonstrating how to run a
freestanding guest kernel with Linux KVM, including an optional Arm CCA Realm
execution path. The VMM is written in Rust; the guest kernel is written in C
and AArch64 assembly.

This is a research / learning prototype, not a production VMM or a security
certification. Realm mode depends on Arm RME hardware and matching host-kernel
KVM support.

## What it contains

- `src/main.rs` — KVM-backed VMM, guest memory setup, virtual UART and guest
  hypercall handling.
- `src/kernel/` — freestanding guest kernel, including exception handling,
  memory management, UART, RSI and syscall support.
- `src/user/test.s` and `src/user/test.elf` — a small AArch64 user-mode test
  program used by the guest.

The guest currently boots a fixed kernel image from
`src/kernel/kernel_start.bin`. The kernel build creates this file; it is
git-ignored and is not included in the repository.

## Requirements

- A Linux AArch64 host with `/dev/kvm` and a compatible KVM-enabled kernel.
- For Realm mode, an Arm CCA / RME-capable platform and host KVM support for
  Arm Realms.
- Rust and Cargo for building the VMM.
- GNU GCC and binutils for building the guest kernel. The kernel Makefile uses
  `-march=native`, so build it on the target AArch64 host.
- Permission to access KVM (the examples below use `sudo`).

## Build

From the repository root:

```sh
make buildk
make build
```

`make buildk` builds `src/kernel/kernel_start.bin`; `make build` builds the Rust
VMM at `target/debug/arm-cca-example`.

## QEMU Arm CCA development host

The `build-image/` directory contains scripts for creating an Ubuntu guest on
a QEMU Arm CCA platform, useful when a native CCA host is unavailable. Follow
[`build-image/README.md`](build-image/README.md): run `./prebuild.sh -a`, start
listeners on ports `54323` and `54324`, then launch with
`./qemu_launch_host.sh`. Once connected to the guest, build and run this project
using the commands above.

## Run

Run the guest as an Arm CCA Realm:

```sh
make run
```

The `run` target invokes the VMM with `-r` (Realm mode) using `sudo`. To run
without Realm mode instead:

```sh
sudo ./target/debug/arm-cca-example
```

The command-line options are:

| Option | Description |
| --- | --- |
| `-r`, `--realm` | Create and run a Realm VM. |
| `-d`, `--debug` | Enable the VMM's debug mode. Realm and debug modes cannot be combined. |
| `-a`, `--address <address>` | Set the guest RAM address; defaults to `0x42000000`. |
| `-h`, `--help` | Show help. |

Use `./target/debug/arm-cca-example --help` for the CLI generated by the
current build. The guest reports output through the emulated UART to the
terminal.

## Notes

- `make run` expects both build steps above to have completed.
- The project uses KVM interfaces specific to Arm, and its Realm path relies on
  Arm RME KVM extensions; it will not run on a typical x86 host or a host
  without those extensions.
- `src/kernel/README.md` contains an older QEMU/GDB note for the guest kernel;
  it is separate from the KVM VMM run path described here.
